A labelled dataset of SSH sessions recorded by a [Cowrie](https://github.com/cowrie/cowrie)
honeypot in an isolated lab. Every session was produced by a scripted client following one of seven
behaviour profiles (one benign, six attack), so every row has a ground-truth category. One category,
`exfiltration`, appears only in the evaluation split so that it can serve as an unseen behaviour for
novelty and zero-day detection experiments.

> **Read this first.** This is **controlled, generated traffic**, not a capture of real attackers.
> All sessions come from a single source address, timing is compressed about 8×, and several
> feature columns are proxies or constants (see [Known limitations](#known-limitations)). The value
> of the dataset is labelled, reproducible behaviour, not realistic network origins.

## Quick start

```python
import pandas as pd

train = pd.read_csv("train/features.csv")
eval_ = pd.read_csv("eval/features.csv")

# Drop identifiers and columns that are constant or split-dependent (see Known limitations)
drop = ["session_id", "src_ip", "src_port", "proto", "service", "sttl", "dttl",
        "ct_srv_src", "ct_state_ttl", "ct_dst_ltm", "ct_src_ltm", "ct_srv_dst", "synack"]
X_train = train.drop(columns=drop + ["attack_cat", "label"])
y_train = train["attack_cat"]

# Optional: keep only sessions that executed commands
train_active = train[train["spkts"] > 1]   # spkts counts 'exit' too
```

## Splits and intended use

- **train** (seed {train_seed}): the six non-held-out categories. Use as training or reference
  ("known behaviour") data.
- **eval** (seed {eval_seed}): all seven categories including `exfiltration`. Use for evaluation,
  and in particular to test whether a method flags `exfiltration` as novel.
- The splits come from independent generation runs and share **no session IDs**.

Suitable for: behaviour clustering, supervised session classification, novelty / open-set
detection, and testing honeypot log pipelines. Not suitable for: estimating real-world attack
prevalence, IP-reputation work, or packet-level intrusion detection.

## Known limitations

1. **Generated, single-source traffic.** Every session comes from `172.19.0.1`. IP-based analysis
   is meaningless here.
2. **Split-dependent constant columns.** `ct_srv_src`, `ct_dst_ltm`, `ct_src_ltm` and `ct_srv_dst`
   each equal the number of sessions in their split (3125 in train, 1232 in eval). They carry no
   behavioural information and **differ between splits**, so a model that uses them can separate
   train from eval for reasons unrelated to behaviour. Drop them.
3. **Proxy features.** Columns named after packets and bytes (`spkts`, `dpkts`, `sbytes`, `dbytes`)
   count commands, server events, command text and TTY recording size. `tcprtt` is SSH key-exchange
   delay. `synack` is a fixed fraction (0.45) of `tcprtt`. `sttl`, `dttl`, `ct_state_ttl`, `proto`
   and `service` are constant.
4. **Compressed timing.** Delays were divided by 8 during collection. Relative pacing between
   categories is kept; absolute values are not human-scale.
5. **Many zero-command sessions.** Each failed login is its own session. {zero_cmd_total} of
   {total_sessions} sessions ({zero_cmd_pct}) executed no command, most of them in `brute_force`,
   and many share identical feature values. Filter them if you need behaviour-bearing sessions only.
6. **Emulated outcomes.** Cowrie emulates a shell, so downloads, executions and uploads did not
   really happen.
7. **One held-out category.** Novelty experiments on this data test one unseen behaviour.
