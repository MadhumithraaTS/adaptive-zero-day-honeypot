## Origin and dependencies
- **Origin:** every file was produced by `reports/attribution_trust_boundary_remediation_20261111/validate_remediation.py` (Task 26C).
  - `input/` was written by that script on the host.
  - `output/<case>/` was written by the isolated `threat-assessment` container (uid 999), one directory per validation case.
- **What depends on them:**
  - `cowrie/docker-compose.yml` mounts the two **directories** (`./assessment_work/input:/work/input:ro`, `./assessment_work/output:/work/output`). The directories should stay, even if empty; Docker would recreate them, but keeping them avoids surprises.
  - `validate_remediation.py` empties and re-populates them each time it runs.
  - No configuration, code path, report or SHA256SUMS manifest references any individual file in them. The Task 26C manifest covers its own `evidence/` copies, not these files.
- **Live components:** none reads them. Only the profiled assessment service mounts them, and it is not running.
